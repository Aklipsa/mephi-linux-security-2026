## Раздел 1. Создание пользователя (пошагово: отдельно группа, пользователь, добавление в группу)

Здесь создание пользователя и добавление в группу разделены на независимые операции — это отражает правильную практику администрирования, когда группы создаются централизованно, а пользователи добавляются в них позже.

| Шаг | Команда | Что происходит на этом шаге |
| --- | --- | --- |
| 1 | `groupadd -f students` | Создаётся группа `students`. Флаг `-f` предотвращает ошибку, если группа уже существует. |
| 2 | `useradd -u 1234 -m user1` | Создаётся пользователь `user1` с UID 1234 (`-u 1234`) и домашней директорией (`-m`). Добавление в группу **не выполняется** на этом этапе. |
| 3 | `usermod -aG students user1` | Пользователь `user1` добавляется в группу `students`. Флаг `-a` (append) критически важен: он добавляет пользователя в группу, не удаляя его из других групп; `-G` указывает целевую группу. |
| 4 | `passwd user1` | Устанавливается пароль для `user1`. Система запросит дважды ввести пароль — без этого вход невозможен. |
| 5 | `chage -M 90 user1` | Задаётся максимальный срок действия пароля — 90 дней (смена каждые три месяца). |
| 6 | `id user1` | Проверка результата: выводится UID, основная группа и список дополнительных групп (должно быть видно, что `user1` состоит в `students`). |
| 7 | `chage -l user1` | Подтверждение настройки политики пароля (срок действия 90 дней). |

**Артефакты раздела 1 (доступны для проверки, но не собираются в этом разделе):**
- `/etc/passwd` — данные о созданном пользователе.
- `/etc/shadow` — хеши паролей и политики паролей (включая срок действия).
- `/etc/group` — информация о группе `students` и членстве в ней.

## Раздел 2. Мониторинг файлов и процессов

**Выполняемые команды:**

| Команда | Действие и объяснение |
| --- | --- |
| `find / -perm -4000 -type f 2>/dev/null` | Ищет все файлы с SUID-битом (`-perm -4000`) по всей ФС. `-type f` — только файлы. `2>/dev/null` — скрывает ошибки доступа. Вывод показывается в терминале. |
| `ps -eo pid,euid,ruid,comm \| awk '$2==0 && $3>=1000'` | Выводит процессы, где EUID=0 (root), а RUID≥1000 (обычный пользователь). Это процессы, запущенные обычным пользователем, но выполняемые с правами root (часто через SUID). |

> Если подходящих процессов нет — запустите `passwd` в одном терминале и сразу выполните команду с `ps` в другом, чтобы «поймать» процесс.

**Артефакты раздела 2:**
- Список SUID‑файлов.
- Снимок процессов с повышенными привилегиями.

## Раздел 3. Механизм set-UID (на примере `cat`)

**Выполняемые команды:**

| Команда | Действие и объяснение |
| --- | --- |
| `cp /bin/cat /home/user1/mycat` | Копирует системную утилиту `cat` в домашнюю директорию `user1` как `mycat`. |
| `chown root:root /home/user1/mycat` | Назначает владельцем файла `root:root`. Это обязательное условие для работы SUID. |
| `chmod u+s /home/user1/mycat` | Устанавливает SUID-бит. Теперь при запуске `mycat` будет выполняться с правами владельца (root). |
| `ls -la /home/user1/mycat` | Проверяет права: в позиции владельца должна быть буква `s` (например, `-rwsr-xr-x`). |
| `su - user1 -c '/home/user1/mycat /etc/shadow'` | Запускает `mycat` от имени `user1`. Благодаря SUID программа читает `/etc/shadow` (обычно доступен только root). |
| `su - user1 -c 'cat /etc/shadow'` | Запускает обычный `cat` от имени `user1`. Получит ошибку `Permission denied` — подтверждение разницы. |

## Раздел 4. Механизм привилегий (capabilities) на примере `chown`

**Выполняемые команды:**

| Команда | Действие и объяснение |
| --- | --- |
| `cp /bin/chown /home/user1/mychown` | Копирует утилиту `chown` в домашнюю директорию `user1` для экспериментов. |
| `setcap cap_chown+ep /home/user1/mychown` | Назначает capability `cap_chown` (право менять владельца). `+ep` — флаги effective и permitted. |
| `getcap /home/user1/mychown` | Проверяет, что capability назначена (вывод: `/home/user1/mychown = cap_chown+ep`). |
| `su - user1 -c 'touch /home/user1/testfile'` | Создаёт тестовый файл от имени `user1`. Владельцем будет `user1`. |
| `su - user1 -c '/home/user1/mychown root /home/user1/testfile'` | Меняет владельца файла на `root` через `mychown`. Работает благодаря `cap_chown`, без полных прав root. |
| `ls -la /home/user1/testfile` | Проверяет нового владельца: должен быть `root`. |

## Раздел 5. Механизм sudo

**Выполняемые команды:**

| Команда | Действие и объяснение |
| --- | --- |
| `echo "user1 ALL=(root) /usr/sbin/date, /usr/sbin/timedatectl, /usr/sbin/hwclock" > /etc/sudoers.d/user1` | Добавляет правило для `user1`, разрешающее менять время только указанными командами. |
| `visudo -c -f /etc/sudoers.d/user1` | Проверяет синтаксис файла. Без этой проверки sudo может не принять правило. |
| `chmod 440 /etc/sudoers.d/user1` | Устанавливает безопасные права: только root может читать файл. Это требование безопасности для правил sudo. |
| `su - user1 -c 'sudo timedatectl set-time 12:00:00'` | От имени `user1` меняет системное время через sudo. Команда разрешена правилом выше. |
| `timedatectl` | Выводит текущее время — подтверждает, что изменение прошло успешно. |

**Артефакт раздела 5:**
- Файл в `/etc/sudoers.d/` — настроенные правила sudo для пользователя `user1`.

## Раздел 6. Сбор артефактов

Все команды ниже выполняются **только в этом разделе**, строго в указанном порядке. Они фиксируют результаты предыдущих действий.

| Команда | Назначение артефакта | Соответствие списку артефактов |
| --- | --- | --- |
| `history > ~/history.out` | Сохраняет историю команд текущей сессии. Содержит все выполненные команды. | `history.out` — Все |
| `stat /home/user1 > ~/stat.out` | Метаданные домашней директории пользователя. | Начало `stat.out` |
| `stat /home/user1/mycat >> ~/stat.out` | Дописывает метаданные утилиты `mycat` (SUID). | Продолжение `stat.out` (раздел 3) |
| `stat /home/user1/mychown >> ~/stat.out` | Дописывает метаданные утилиты `mychown` (capabilities). | Продолжение `stat.out` (раздел 4) |
| `getcap /home/user1/mycat > ~/getcap.out` | Capabilities для `mycat` (будет пусто — используется SUID). | Начало `getcap.out` |
| `getcap /home/user1/mychown >> ~/getcap.out` | Capabilities для `mychown` (должна быть строка `cap_chown+ep`). | Продолжение `getcap.out` (раздел 4) |
| `find / -perm -4000 -type f 2>/dev/null > ~/suid_files.out` | Список всех файлов с SUID (включая системный и `mycat`). | Файл с выводом команды поиска файлов (раздел 2) |
| `ps -eo pid,euid,ruid,comm \| awk '$2==0 && $3>=1000' > ~/proc_monitor.out` | Снимок процессов с EUID=0 и RUID≥1000. | Файл с выводом команды мониторинга процессов (раздел 2) |

## Важные примечания

- **Команды для артефактов выполняются только в разделе 6.** В разделах 1–5 артефакты не создаются — только настраивается среда и демонстрируются механизмы.
- Все изменения (пользователь, правила sudo, права файлов, capabilities) сохраняются после перезагрузки.
- Команды выполняются от root либо через `sudo`.
